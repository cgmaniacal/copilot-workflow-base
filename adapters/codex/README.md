# Codex Adapter

Generates `AGENTS.md` for projects using OpenAI Codex CLI (ChatGPT's terminal coding agent).

OpenAI Codex reads `AGENTS.md` at the project root to provide persistent AI instructions across all sessions.

## What this adapter generates

| File | Description |
|------|-------------|
| `AGENTS.md` | Codex's persistent instructions file, written at higher verbosity for ChatGPT |

The generated file includes:

1. A header comment noting it was generated by ai-workflow-overlay
2. A verbose 4-phase Development Workflow (Research → Plan → Implement → Validate) with explicit step-by-step instructions per phase
3. Core Principles as a numbered list with bold emphasis
4. Shared slim content via `buildSlimContent` (git conventions, agent docs reference, documentation requirements, implementation guards)
5. Branch Access Rules via `buildBranchAccessRules` with a CRITICAL reinforcement statement
6. A Common Mistakes section with ChatGPT-specific guardrails

## Design decisions

**Higher verbosity than CLAUDE.md.** ChatGPT benefits from step-by-step instructions rather than concise summary tables. Each workflow phase lists explicit numbered steps so the model knows exactly what to do at each stage.

**Instruction-based branch protection only.** Unlike the Claude adapter, the Codex adapter has no mechanism to inject deny rules into a settings file. Branch protection is enforced purely via clear written instructions in the AGENTS.md and a CRITICAL reinforcement statement after the Branch Access Rules section.

**Common Mistakes section.** This section addresses failure modes that are especially common with ChatGPT-based agents: placeholder code, skipping agent_docs, scope creep, and false test-pass claims. It is placed at the end so it is easily referenced.

## When to regenerate

Regenerate after:
- Editing any file in `agent_docs/`
- Updating `core/workflow.md`
- Changing branch configuration in the overlay config

## How to regenerate

From the project root, run the onboarding script (which calls this adapter):

```bash
node scripts/onboard.mjs
```

Or call the adapter directly from a script:

```javascript
import { generateCodexConfig } from './adapters/codex/generate.mjs';

generateCodexConfig(
  '/path/to/target-project',           // project being onboarded
  '/path/to/overlay/core',             // overlay's core/ directory
  '/path/to/target-project/agent_docs' // populated agent_docs in target project
);
```

## Notes

- `AGENTS.md` is written directly at the project root — no subdirectory is created.
- No external dependencies — uses only Node.js built-ins.
- Branch access rules are generated dynamically from `overlayConfig.branchConfig`, with a sensible default if no config is provided.
