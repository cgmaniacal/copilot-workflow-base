# CI Templates

Generated by ai-workflow-overlay. Two pipeline templates are provided — one for GitHub Actions and one for Azure DevOps. Both implement the same three-stage CI flow: lint, test, and build.

## Files

| File | Platform |
|------|----------|
| `github-actions.yml` | GitHub Actions (copy to `.github/workflows/ci.yml`) |
| `azure-pipelines.yml` | Azure DevOps (copy to the repo root as `azure-pipelines.yml`) |

## Placeholders

Replace every `{{PLACEHOLDER}}` token before committing the pipeline file to your repository.

| Placeholder | Purpose | Examples |
|-------------|---------|---------|
| `{{SETUP_STEPS}}` | Runtime environment setup steps | `actions/setup-node@v4` (GitHub), `NodeTool@0` (Azure) |
| `{{INSTALL_COMMAND}}` | Install project dependencies | `npm ci`, `pip install -r requirements.txt`, `dotnet restore` |
| `{{LINT_COMMAND}}` | Run linting and formatting checks | `npm run lint`, `ruff check .`, `dotnet format --verify-no-changes` |
| `{{TEST_COMMAND}}` | Run the test suite | `npm test`, `pytest`, `dotnet test` |
| `{{BUILD_COMMAND}}` | Produce a production build artifact | `npm run build`, `python -m build`, `dotnet publish -c Release` |

## Usage

### GitHub Actions

1. Copy `github-actions.yml` to `.github/workflows/ci.yml` in your project.
2. Replace all `{{PLACEHOLDER}}` tokens with the correct commands for your stack.
3. Expand the `# {{SETUP_STEPS}}` comment into one or more `- uses:` steps. For a Node.js project this looks like:

```yaml
- uses: actions/setup-node@v4
  with:
    node-version: 'lts/*'
    cache: 'npm'
```

### Azure DevOps

1. Copy `azure-pipelines.yml` to the root of your repository.
2. Replace all `{{PLACEHOLDER}}` tokens with the correct commands for your stack.
3. Expand the `# {{SETUP_STEPS}}` comment into one or more `- task:` steps. For a Node.js project this looks like:

```yaml
- task: NodeTool@0
  inputs:
    versionSpec: '20.x'
  displayName: Install Node.js
```

4. In Azure DevOps, create a new pipeline and point it at the file in your repository.

## Pipeline Behavior

Both templates share the same logical flow:

- Triggered on pushes to `develop` and on pull requests targeting `main` or `develop`.
- The `lint` and `test` jobs run in parallel.
- The `build` job only runs after both `lint` and `test` pass.
