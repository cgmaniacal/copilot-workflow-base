# AI Workflow Overlay — Design Document

**Date:** 2026-03-02
**Status:** Approved
**Scope:** Transform `copilot-workflow-base` (React/TypeScript boilerplate) into `ai-workflow-overlay` (platform-agnostic AI development workflow for existing projects)

---

## Problem

The current repo is a React/TypeScript project scaffolder with embedded AI workflow optimizations (4-phase Superpowers workflow, memory system, implementation guards, agent_docs). The workflow layer is valuable across any tech stack and any AI agent, but it's tightly coupled to one platform.

## Goals

1. Extract the universal workflow into a platform-agnostic overlay
2. Support onboarding into existing projects (React/TS, WordPress, .NET/C#, Python, generic)
3. Make GitHub Copilot the primary agent, with adapters for Claude Code and Cursor
4. Observe and document existing project patterns — never prescribe or override them
5. Support both GitHub Actions and Azure DevOps CI pipelines

## Non-Goals

- Code generation / project scaffolding
- Replacing existing conventions in target projects
- Building a framework or runtime dependency

### Three Layers

**Core** — Platform-agnostic workflow. The 4-phase process (Research → Plan → Implement → Validate), implementation guards, documentation requirements, and template-based agent_docs. This is always installed.

**Adapters** — Agent-specific config generators. Translate the universal workflow into each AI agent's native format. Copilot config is generated by default (primary agent). Claude Code and Cursor adapters are optional.

**Stacks** — Detection patterns and documentation guidance for each supported platform. Tell the onboarding agent what to look for and how to document it. Multi-stack projects are supported.

## Core Principles

### Observe First, Prescribe Never

Agent docs describe reality. They are a reference for understanding the project, not a mandate for changing it. If an existing pattern conflicts with a template's suggestions, the existing pattern wins.

The onboarding agent documents what exists — it does not impose opinions on architecture, auth, conventions, or patterns. Flag genuinely problematic patterns (security vulnerabilities, data loss risks) as observations, not automatic fixes.

### Copilot-First

GitHub Copilot is the primary agent. The core workflow and instruction format are optimized for Copilot's conventions. The `core/workflow.md` maps directly to `.github/copilot-instructions.md` without translation. Other agents receive translated config via adapters.

### Universal Workflow

The 4-phase process works regardless of stack or agent:
1. **Research** — Understand the problem, explore the codebase, document findings
2. **Plan** — Break work into small tasks with exact file paths
3. **Implement** — Follow TDD, commit after completing implementation
4. **Validate** — Evidence before claims. All quality gates must pass.

### Stack Detection, Not Stack Opinion

Onboarding discovers and documents. A WordPress project with a React frontend and a Python microservice detects all three. Each detected stack populates its relevant agent_doc sections.

## Agent Docs: Template-Based Discovery

Templates are stripped of platform specifics and rewritten as discovery prompts — instructions to the onboarding agent about what to look for.

### Always Generated

| Template | What it captures |
|----------|-----------------|
| `building_the_project.md` | Build commands, dev server, env vars, project structure — recorded from actual config files |
| `code_conventions.md` | Naming, file structure, import style — analyzed from existing code, not prescribed |
| `running_tests.md` | Test framework, commands, patterns, co-location — detected from project |
| `service_architecture.md` | Layer separation, services, state management — mapped from actual structure |
| `branching_workflow.md` | Git workflow, CI triggers — mostly prescriptive but detects existing conventions first |
| `audit_skills.md` | Quality audit process — genericized, stack-specific targets added per detection |
| `memory_system.md` | Memory commands and architecture — already platform-agnostic |
| `dependency_updates.md` | Update strategy, package manager specifics — detected from project |

### Conditionally Generated

| Template | Generated when |
|----------|---------------|
| `authentication.md` | Auth middleware, JWT, OAuth, session management detected |
| `database_schema.md` | ORM, migration files, database config detected |
| `frontend_quality.md` | Frontend framework detected (React, Vue, WordPress theme, etc.) |
| `service_communication.md` | API layer, microservices, or client-server communication detected |

## Adapters

### GitHub Copilot (Default)

Generates `.github/copilot-instructions.md` directly from the populated core files. No translation needed — the core format is Copilot-native.

### Claude Code (Optional)

Generates:
- `CLAUDE.md` — synthesized from `core/workflow.md` + agent_doc references
- `.claude/settings.json` — permissions with stack-appropriate hooks
- `.claude/hooks/` — workflow hooks + stack-detected post-edit hook (tsc for TS, php -l for PHP, dotnet build for C#, mypy/ruff for Python)
- `.claude/agents/` — memory-locator, memory-writer
- `.claude/commands/` — remember, recall, memory-status
- `.claude/skills/` — memory, remember, recall

The memory system is a Claude-specific bonus — too tightly coupled to Claude's hooks/agents model to abstract.

### Cursor (Optional)

Generates `.cursorrules` from the populated core files.

## Onboarding Flow

```
1. Pre-flight checks
   ├── Verify git repo
   ├── Check for existing overlay (offer update)
   └── Warn on uncommitted changes

2. Stack detection
   ├── Scan against stacks/*/detect.md signals
   ├── Report: "Detected: React/TypeScript, WordPress"
   └── Confirm with user (allow override)

3. Agent selection
   ├── Copilot config by default
   └── Ask: "Also generate for: Claude Code / Cursor / None"

4. CI detection
   ├── Scan for existing CI config
   ├── If found: offer to extend with quality gates
   ├── If not found: ask GitHub Actions / Azure DevOps / Both / Skip
   └── Generate or extend pipeline

5. Project analysis (agent-driven)
   ├── Agent traverses project guided by stack templates.md
   ├── Reads config files, sample source, existing docs
   ├── Populates agent_doc templates with observed patterns
   └── Flags notable observations (no tests, no linter, etc.)

6. File generation
   ├── Copy docs/ skeleton (decisions/, research/, plans/)
   ├── Write populated agent_docs/
   ├── Write Copilot config (always)
   ├── Run selected adapter generators
   └── Write CI config if applicable

7. Summary
   ├── List files created/modified
   ├── Note observations
   └── Suggest next steps
```

The onboarding script is idempotent — safe to re-run. Re-detects stacks, offers to update agent_docs (preserving manual edits), adds new adapter configs without clobbering existing ones.

Step 5 delegates to the AI agent running the script. When run via Claude Code, the agent uses its tools. When run via Copilot chat, the user works through the analysis prompt interactively. When run manually, skeleton files are generated with TODO markers.

- `scripts/templates/` (all code generation templates)
- `renovate.json`

- `CLAUDE.md` → `core/workflow.md` (universal, Copilot-native) + Claude adapter regenerates CLAUDE.md from it

- `stacks/*/detect.md` and `templates.md` for each stack
- Adapter generators for Copilot, Claude, Cursor
- Rewritten README

## What the Overlay Gives Any Project

- Structured AI workflow (brainstorming, planning, TDD, debugging, code review)
- Auto-documented project structure and conventions
- ADR framework
- CI quality gates (lint, test, build)
- Implementation guards (blast radius checks, checkpoints, guardrails)
- Claude Code memory system (when Claude adapter is selected)
